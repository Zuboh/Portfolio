# SEO audit — zubodev.vercel.app (2026-10-23)

Skill: `seo-audit`. Scope: full site (12 sitemap URLs, en + it), technical + on-page + international. Context: `.agents/product-marketing.md`.
Data: live production after PR #6, collected with a fetch-based crawler (all JSON-LD is server-rendered, so static HTML is complete) and `scripts/seo-check.mjs` (passed, 12 URLs).
Not available: Search Console / Bing data (properties not set up yet), backlink data. Core Web Vitals not re-measured (Lighthouse mobile 95–100 on 2026-10-17).

## Executive summary

Technical foundations are healthy: crawlable, indexable, correct canonicals, valid reciprocal hreflang, clean sitemap, HTTPS + HSTS, real 404s, no orphan pages, no broken internal links. The site is new to the index, so the biggest remaining levers are **titles** and **getting indexed at all**.

Top issues:
1. **Every page except /hire has the title "Lorenzo Zubani"** (10 of 12 URLs, 14 characters). The strongest on-page ranking signal carries no role, stack or location, and is duplicated site-wide.
2. **Search Console and Bing Webmaster Tools not set up**, so no sitemap has been submitted and indexing can't be checked.
3. **og:url / og:title on /resume and /work/\* point to the home page**, so links shared on LinkedIn or Slack show the home card.
4. **Thin case study**: /en/work/primo has 163 words. Case studies also lack measurable outcomes.
5. **Short résumé descriptions** (88 en / 95 it characters).

Quick wins: 1, 3 and 5 are copy/metadata changes in one PR.

**T1 — Search Console / Bing not configured.** Impact High · Priority 1
- Evidence: no property exists for `zubodev.vercel.app`, so the sitemap was never submitted.
- Fix: GSC URL-prefix property → submit sitemap → URL Inspection "Request indexing" for `/en`, `/it`, `/en/hire`, `/it/hire`. Bing Webmaster Tools → import from GSC. `npm run seo:indexnow -- https://zubodev.vercel.app`.

**T2 — Uppercase locale path.** Impact Low · Priority 5
- Evidence: `/EN` → 307 `/en/EN` → 404.
- Fix: optional; lowercase the path in `src/proxy.ts` before prefixing. Nobody links to it today.

## International (en / it)

- `<html lang>` matches locale on all 12 URLs.
- hreflang `en`, `it`, `x-default` on every page, self-referencing and reciprocal, all 200 and canonical.
- Main content fully translated (headings and body differ per locale, not just chrome).
- Optional for Bing: `<meta http-equiv="content-language">` (Bing treats hreflang as a weak signal). Low priority.

## On-page findings

**O1 — Duplicate, keyword-less titles.** Impact High · Priority 1
- Evidence: `<title>Lorenzo Zubani</title>` on /en, /it, /en|it/resume and all 6 /work pages. Only /hire has its own title. The root layout sets `title: SITE_NAME` with no template, and no child page overrides it.
- Fix: in `src/app/[lang]/layout.tsx` use `title: { default: <home title>, template: '%s · Lorenzo Zubani' }`. Then set:
  - Home: `Lorenzo Zubani · Frontend Engineer, React & Next.js · Brescia` (~60 chars). it: `Lorenzo Zubani · Frontend Engineer React e Next.js · Brescia`.
  - Résumé: `Résumé, Frontend Engineer` / `Curriculum, Frontend Engineer` → rendered with the template.
  - Case study: `<Project>: <short what-it-is>` (e.g. `Primo: AI contract and payslip reader`).
  - Hire: keep the current explicit titles (set `title.absolute` so the template doesn't double the name).
  - Add an assertion to `seo-check.mjs`: titles unique across the sitemap and 30–65 chars.

**O2 — Share metadata inherited from home.** Impact Medium · Priority 2
- Evidence: `og:url` on /en/resume = `https://zubodev.vercel.app/en`; same on all /work pages. `og:title` is the home title.
- Fix: per page, set `openGraph` with own `url`, `title`, `description` and `images` (same pattern as /hire; overriding `openGraph` drops the segment image). Extend the `og:url not self` assertion in `seo-check.mjs` from /hire to every URL.

**O3 — Short résumé descriptions.** Impact Low · Priority 3
- Evidence: 88 (en) / 95 (it) chars; no stack or location.
- Fix: ~150 chars, e.g. `Résumé of Lorenzo Zubani, Frontend Engineer in Brescia: React, Next.js, TypeScript, design systems. Experience at Accenture, Codiceplastico and startups.`

**O4 — H1s are names only.** Impact Low · Priority 4
- Evidence: home and résumé H1 = "Lorenzo Zubani"; role sits in a `<p>` above.
- Fix: none needed for the brand query; the title fix (O1) carries role + stack. Don't change the visual H1.

**O5 — Images.** Impact Low · No action
- 42 images on home, all with `alt=""`: they are decorative illustrations and stack icons beside visible text labels, so empty alt is correct. The résumé portrait has descriptive alt.

## Content findings

**C1 — Case studies lack outcomes; Primo is thin.** Impact Medium · Priority 2
- Evidence: words per page: Eira 443, Zubo OS 328, Primo 163 (en). No numbers (users, time saved, performance, scope).
- Fix: add an "Outcome" or "Results" section per case study with 2–3 verifiable facts (scope, what shipped, metrics if any). Bring Primo to ~350+ words. This matters for recruiters and for AI citation (see ai-seo).

**C2 — E-E-A-T.** Status: good for a portfolio. Real name, location, résumé with employers and dates, contact email, GitHub/LinkedIn links. Missing: third-party mentions (authority), which is the off-site task 8.
